# 火龙探险开发记录

[返回项目首页](../README.md)

## 1. 开发顺序

项目使用Unity 2022.3.62f3c1开发。最初先搭出一段可以移动和跳跃的场景，再加入攻击、敌人和机关，最后补齐检查点、重生、通关和菜单。

调试时主要关注三个问题：角色动作能否正确切换，碰撞后的伤害与反馈是否一致，以及重生、暂停、重开之后能否继续正常操作。

## 2. 模块职责与调用关系

| 模块 | 职责 |
| --- | --- |
| PlayerController2D | 输入、刚体移动、朝向、动画参数、火球和奔跑特效生成 |
| Fireball2D | 火球方向、速度、存活时间与命中处理 |
| BirdEnemy2D | 范围巡逻、帧动画、接触伤害、死亡与击杀加分 |
| Hazard2D / MovingBallHazard2D | 炸弹、掉落区域及往返球体伤害 |
| LevelManager2D | 生命、分数、检查点、重生、暂停和通关 |
| Checkpoint2D / Goal2D / CollectibleCoin | 检查点、终点和金币触发 |
| CameraFollow2D | LateUpdate中的横向平滑跟随 |
| AudioManager2D | 背景音乐、操作音效与静音 |
| MainMenuController / TextColorCycle | 主菜单操作与标题颜色变化 |

```text
输入 -> PlayerController2D -> Rigidbody2D + Animator
攻击 -> Fireball2D -> BirdEnemy2D.TakeHit -> 死亡表现与加分
伤害 / 金币 / 旗子 -> LevelManager2D -> UI、音频与关卡流程
角色位置 -> CameraFollow2D -> 横向镜头跟随
```

## 3. 开发过程中的关键处理

### 动画过渡与参数配置

开发时遇到过待机切到攻击、跳跃后不恢复跑步，以及Animator参数不存在的报错。我把问题分成角色运动和动画表现两部分：先观察刚体位置与速度，确认移动或起跳是否执行，再检查Animator当前状态、参数值和过渡条件。

移动状态主要看Speed，空中状态结合OnGround和VerticalSpeed，攻击由Attack触发。调试过渡时，重点检查起跳是否被Has Exit Time延后、攻击是否误设为循环，以及动作结束后是否有返回移动状态的出口。脚本初始化时检查参数名称和类型，更新时使用缓存的检查结果。

### 火球和特效的位置

火球、奔跑拖尾都出现过“对象生成了，但画面里看不到”的情况。排查时先确认Sprite引用，再检查出生位置、缩放和Sorting Layer / Order，最后检查生命周期。

代码中为火球和拖尾分别设置发射点与偏移，角色转向时同步调整火球的出生位置和方向。特效的渲染顺序也单独配置，避免被背景或地面遮住。这样调整火球大小和嘴部位置时，不需要同时改角色本身的缩放。

### 伤害、血条与重生

敌人、炸弹和球体分别提交伤害值，由LevelManager2D统一扣血并刷新UI。检查点只更新返回位置，生命归零或掉落时再启动重生。

针对重生期间重复受伤的问题，入口增加isRespawning判断，重生时关闭角色控制，传送后清空速度并恢复生命。血条显示异常则单独检查Image或RectTransform的更新，确保绿色生命区和红色损失区使用同一个生命比例。

### 命中和死亡结算

攻击请求由角色控制器处理冷却，火球实例负责飞行和命中。鸟敌人的死亡逻辑先检查并设置dead，再关闭碰撞、播放死亡表现和增加分数。即使同一帧收到多个命中，死亡分支也只处理一次。

后续准备重点补测贴身发射和低帧率命中，并调整火球出生保护与路径检测，具体安排放在README的后续开发思路中。

### 编辑器与构建中的资源引用

一些特效在编辑器里能通过AssetDatabase找到资源，但网页运行时无法执行编辑器接口。因此打包前检查场景和预制体引用，把需要的Sprite序列写入序列化字段，再验证构建后的实际效果。

中文按钮和标题也放到构建版本中检查，确认字体、文字和资源一起进入发布包。

## 4. 打包与验证

1. 使用Unity 2022.3.62f3c1及对应的WebGL Build Support。
2. 检查Console、角色组件、火球预制体、音频与特效引用。
3. 将MainMenu和GameLevel按顺序加入Build Settings。
4. 分别导出Windows和WebGL版本；WebGL通过HTTP加载运行。
5. 在构建版本中检查进入关卡、移动跳跃、火球攻击、扣血、检查点、重生和通关，并补测暂停后重开。
